## 动作设计

土豆整体为一个刚体（脸不在皮上滑动、红钮不脱离），底部接地不动、不横滑。弹性起伏：第3帧压缩极限（最低），第7帧伸展极限（最高，红钮完整可见），第6帧先下蹲再弹起。眨眼仅出现在第4-6帧附近。

1. 正常睁眼 → 2. 压低一半 → 3. 压缩极限 → 4. 回正 → 5. 正常闭眼 → 6. 下蹲 → 7. 伸展极限睁眼 → 8. 回中接首帧。

## 已知事项

- 本次 `background:"transparent"` 参数未生效（生成图为 RGB 棋盘格底），已用「棋盘双色 + 边缘连通域」算法去背（保护角色内部眼白/高光不被误删），柔边 0.6px 高斯；深底检查无残留。生成器在右下格注入的浅灰 AI 水印与棋盘格色极度接近，已被同一算法作为背景去除，复检各格角色底缘以下无 alpha 残留。
- 共生成两次：第二次强化了眼睑措辞但丢失了第7帧伸展极限且第3帧压缩过激，故采用第一次结果（起伏节奏完整）。
- 眼睑时序与动作计划有偏差：第3帧为眯眼（计划睁眼）、第4帧睁眼（计划半闭）、第6帧保持闭眼且高度略低于正常（计划上升半睁）；第5帧全闭、第7帧伸展极限正确。播放时读作「压缩时眯眼 → 第5帧闭眼 → 第7帧睁眼」，节奏仍连贯。
- 第6帧高度略低于正常高度（下蹲预备感），与计划的「上升半睁」方向相反；第3帧压缩幅度（约 -18%）大于计划的 -8%，游戏尺寸下更易读。
- AI 生成未严格等格排版，切帧按实际角色区域（见 JSON），游戏接入时逐帧底部锚点对位。
- 当前游戏代码未修改；接入 `sprites.js` 的图片入口待与豌豆射手管线统一后处理。
